# G30D Gen1 3-Cap – real SWD idle measurement (2026-10-10)

**Measured with ST-Link HOTPLUG from the user's actual potted G30D 3-cap controller.** 22 of 22 register reads succeeded. This snapshot is not proof of the exact installed DRV version or permission to flash/energize motor.

## Hardware and GPIO

- STM32F103 medium-density, device ID `0x410`, nominal 128 KiB flash, target 3.29 V.
- `GPIOA_CRH = 0x28842AAA`: PA8/9/10 alternate-function push-pull; **PA11 push-pull output HIGH** (`GPIOA_ODR=0xA800`, `GPIOA_IDR=0xD804`); PA12 floating input HIGH.
- `GPIOB_CRL = 0x4A442404`: **PB1 configured analog input** (nibble 0x0), not a digital gate-enable output in this observed firmware state.
- `GPIOB_CRH = 0xAAA44AE4`: PB12 floating input; PB13/14/15 alternate-function push-pull.
- `GPIOC_CRH = 0x84444444`: **PC14 floating input**, `GPIOC_IDR=0x0000` therefore PC14 LOW at idle. Neither PC14 nor PA12 is *proven* to be the power button by idle-only readings. Short dynamic button test still needed to settle that dispute.

## TIM1 PWM state

| Register | Exact raw value | Interpretation |
|---|---|---|
| `TIM1_CR1` | `0x000000A1` | Center-aligned, enabled, ARR-preload |
| `TIM1_CCMR1` | `0x00006868` | CH1/2 PWM-mode 1 with preload |
| `TIM1_CCMR2` | `0x00006868` | CH3/4 PWM-mode 1 with preload |
| `TIM1_CCER` | `0x00001000` | **Only CH4 enabled. All six CH1..3 and CH1N..3N channel enables off.** |
| `TIM1_ARR` | `0x000007D0` | 2000; PWM frequency cannot be established without PSC/clock snapshot |
| `TIM1_CCR4` | `0x0000076C` | 1900; channel-4 trigger placement |
| `TIM1_BDTR` | `0x0000CD40` | `MOE=1`, **`AOE=1`, `BKE=0`**, OSSR=1, OSSI=1, LOCK=1, DTG=0x40 |

**Important:** In this stationary snapshot `BKE=0`, so there is no enabled TIM1 break input. This does not rule out an independent external analog / driver shutdown path, but no such path has been proved. `MOE=1` does **not** mean the motor outputs are running, since CH1..3 plus complements are disabled via CCER. Future physical motor-off requires validated disabling of *gate commands*, not relying only on three equal 50% CCR values.

## ADC state

- `ADC1_CR1=0x0180`, `ADC1_CR2=0x000E9101`: ADC1 on, external injected trigger from TIM1_CC4 (`JEXTSEL=001`) enabled.
- `ADC1_JSQR=0x00129000`: injected sequence length 2: **JSQ3=ADC1_CH4 (PA4), JSQ4=ADC1_CH5 (PA5)**. These are not simultaneous distinct-ADC samples.
- `ADC2_CR2=0x00000000`, `ADC2_JSQR=0x00000000`: ADC2 off/no injected sequence programmed **in this idle measurement**. This is not enough to conclude ADC2 is unused when the motor is genuinely running.

## Implications for DeltaESC

1. The new PB1-as-analog correction in v0.9.1 is backed by the **real observed GPIO mode**, not solely static disassembly.
2. PC14 power button remains **candidate, not demonstrated**; PA12 floating HIGH at idle is also consistent with a separate input. Do not enable any new GPIO drive from this measurement.
3. TIM1 break is *not* active in current snapshot and **AOE is enabled**. Do not blindly copy BKE/AOE settings into a custom motor release; independently validate comparator/break wiring and fault-reset logic.
4. Revise motor ADC strategy against the observed ADC1 JSQ3=CH4 / JSQ4=CH5, and check real PWM-coherent measurement requirements. Current sensing gain/polarity and motor R/L/flux unqualified.
5. Leave stock/CFW intact and request a second **non-flashing button-state comparison** if safe; **no need to repair halls to gather GPIO data**, assuming Hall wiring does not short the supply.

**Audit result: SWD idle read SUCCESS; firmware motor release remains BLOCKED.**
